# 대상 엔진의 구조와 확인 지점

## 적용 범위

원작의 x86 게임 로직과 자산·저장 형식을 C++로 재구현한 운송 시뮬레이션 계열을 대상으로 한다. 아래 구조는 조사 시작점이며, 현재 설치본과 소스에서 확인한 결과가 우선한다. 실제 버전·경로·문자열 개수는 실행할 때 수집한다.

| 층 | 이 계열의 구조 | 작업에 미치는 영향 |
|---|---|---|
| 게임·UI | C++20, 자체 UI·소프트웨어 렌더러 | 소스 수정·재빌드로 문자열과 그리기를 함께 바꾼다. |
| 빌드·플랫폼 | CMake, Windows MSVC·vcpkg, SDL 계열 플랫폼층 | 현재 소스의 의존성 기준과 OS·아키텍처를 맞춘다. 최신 계열은 SDL3를 사용한다. |
| 번역 | 느슨한 UTF-8 YAML, yaml-cpp, 숫자 문자열 ID | 한국어 파일을 보완하고 명령 토큰을 유지한다. |
| 내부 문자열 | 원작 1바이트 문자표 + 제어 코드 + 바이너리 인수 | UTF-8 파일만 수정해서는 한글 보존을 보장할 수 없다. |
| 기존 폰트 | `g1.DAT`의 글리프 스프라이트 | 기본 4개 글꼴 변형과 제한된 문자 슬롯을 유지·확장한다. |
| 화면 | 8비트 팔레트 RenderTarget, x/y/width/height/pitch | 새 한글 비트맵도 기존 색상·클리핑·좌표계를 따라야 한다. |
| 오브젝트 | DAT 내부 다국어 문자열과 별도 로더 | 화물·선로·역·신호·차량 명칭은 UI 번역과 분리한다. |
| 저장 | 원작 SV5/SC5 계열과 고정 길이 필드 | 표시용 확장과 영구 저장 호환성을 구분한다. |

## 최소 확인 순서

설치 루트의 실행 파일 식별 정보·변경 기록과 대응 소스의 CMake 버전·태그·커밋을 비교한다. 다음 두 축이 함께 맞는지 확인한다.

1. `Data/language` 또는 동등 경로에 `en-GB.yml`, `ko-KR.yml` 등의 YAML이 있고 아래 헤더·숫자 ID 구조를 사용하는가.
2. 소스에 1바이트 변환 함수, G1 글리프 폭 초기화, 바이너리 제어 문자열과 팔레트 렌더러가 연결되어 있는가.

이 확인으로 대상 계열을 식별한 뒤 구현과 관계없는 엔진 전수 조사는 하지 않는다. 원본 실행 파일의 정확한 버전을 찾지 못하면 임의의 최신 소스로 대체하지 말고 현재 확인 수준과 필요한 소스를 구분한다.

## 언어 스키마와 폴백

```yaml
header:
  locale: ko-KR
  english_name: Korean
  native_name: 한국어
  loco_original_id: 9
strings:
  0: ""
  100: "{COLOUR BLACK}{STRINGID} {INT16}"
```

`loco_original_id`는 원작 오브젝트 언어 선택에 연결되는 데이터 필드다. 위 한국어 값은 알려진 스키마의 예이며 현재 열거형과 로더를 대조한다. 헤더의 이름이나 로케일을 임의 번역하지 않는다.

언어 파일을 동적으로 열거하고 `en-GB`를 먼저 읽은 다음 선택 언어로 덮어쓰는 구조가 일반적이다. 한국어가 이미 있으면 별도 로케일이나 다른 CJK 슬롯을 새로 만드는 대신 기존 한국어를 보완한다. 누락 키의 영어 폴백은 유지하되 번역 완료로 계산하지 않는다.

`native_name`도 내부 1바이트 변환을 거치므로 본문과 따로 고쳐야 할 수 있다. UTF-8 저장에 성공해도 변환 중 미지원 코드포인트가 `?`가 되면 그리기 단계에서 원문을 복원할 수 없다.

## 표시 문자열의 코드 범위

아래는 확인할 표시용 제어 코드 그룹이다. 포맷 전의 인수 명령과 포맷 후의 표시 문자열을 구분하고 현재 헤더의 상수로 확인한다.

| 바이트 값·그룹 | 표시 문자열의 해석 |
|---|---|
| `0` | 토큰 사이에서 만났을 때 문자열 종료 |
| `1..4` 그룹 | 제어 코드 1바이트 + 인수 1바이트 |
| `5..16` 그룹 | 줄바꿈·글꼴·외곽선·창 색상 등, 인수 없는 제어 코드 |
| `17..22` 그룹 | 제어 코드 1바이트 + 인수 2바이트 |
| `23..31` 그룹 | 제어 코드 1바이트 + 인수 4바이트 |
| `23` | 알려진 인라인 스프라이트 표시 코드 |
| `24` | 미사용일 때 유니코드 확장 태그로 선택할 수 있는 후보. 현재 버전에서 다시 확인해야 한다. |

다른 팔레트 색상 코드와 티커 전용 표식도 있다. 표만으로 모든 바이트를 분류하는 새 파서를 만들지 말고 엔진의 상수·문맥과 기존 순회 함수를 확장한다.

## 폰트 자산의 의미

기본 G1 폭 초기화는 medium normal·medium bold·small·large의 4종에서 문자 32~255, 각 224개 슬롯을 다룬다. 번역 문자 집합이 이를 넘으면 단순 스프라이트 교체는 용량을 충족하지 못하며 기존 라틴 문자·아이콘도 손상시킬 수 있다.

`hang.dat`, `kanji.dat`, `tai.dat`는 원작 CJK 자산 흔적일 수 있다. 파일 존재와 현재 렌더러의 실제 참조는 다르다. 형식·매핑·로딩·배포 조건이 확인되지 않으면 한글 공급자로 전제하지 않는다. 권장 구현은 기존 G1을 유지하고 별도 재배포 가능 글꼴의 동적 한글 출력 경로를 추가하는 것이다.

## 소스 탐색 지도

소스 루트 접두 경로는 저장소마다 다를 수 있으므로 파일명·함수 서명을 `rg`로 찾는다.

| 파일·영역 | 추적할 내용 |
|---|---|
| `Languages.cpp` | 파일 열거, 헤더·native name, 원작 언어 ID |
| `LanguageFiles.cpp` | YAML 파싱, `{...}` 해석, UTF-8→내부 문자, 영어 폴백 |
| `Conversion.cpp`, `Unicode.cpp` | 문자표, 대체 문자, 코드포인트 디코딩 |
| `Formatting.h/.cpp`, `StringBuffer.cpp`, `StringManager.cpp` | 제어 코드 범위, 인수 소비, 길이·복사·버퍼 |
| `Gfx.cpp`, `Font.h`, `TextRenderer.cpp` | G1 폭·이미지, 그리기·정렬·줄바꿈·자르기 |
| `ObjectStringTable.cpp` | DAT 내장 언어 선택, 오브젝트 문자열 저장 수명 |
| 뉴스·티커·로딩·시나리오·회사·저장 코드 | 포맷 결과를 다른 버퍼에 복사하는 우회 경로 |
| 건설·툴바·드롭다운·툴팁 UI | 한국어 폭·행 높이·여백·상대 좌표 |

이 지도와 패키지의 구현·검증 절차로 시작한다. 특정 외부 문서나 이전 작업 세션이 있어야만 해석되는 지시를 추가하지 않는다.
