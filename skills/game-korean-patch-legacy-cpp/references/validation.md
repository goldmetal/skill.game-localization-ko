# 검증 수준과 문자열 검사 도구

## 변경에 따른 검증 선택

| 변경 | 실제로 확인할 행동 |
|---|---|
| 번역 파일 | 원본 형식 파싱, 중복 ID, 키 범위, 포맷 토큰·인수 |
| 내부 인코딩·토큰 | 코드포인트 왕복, 내장 NULL, 다중 문자 복사, 버퍼 경계에서 안전 절단 |
| 글꼴·렌더러 | 실제 선택 폰트, 필요한 글리프, 기준선·외곽선·폭·클리핑·pitch |
| 줄바꿈·정렬 | 장문·숫자·아이콘 혼합, 여러 줄, 가운데·오른쪽 정렬 |
| UI 간격 | 해당 화면, 다른 배율·장문, 클릭·선택 영역 |
| 버전 이식 | 기존 필수 테스트, 충돌 해결 경로, 새 데이터·주요 화면 |
| 배포 | 원본 백업, 필수 파일, 설치본·압축 내부 해시, 소스 재현 |

검증 결과는 `관찰`, `정적 검증`, `실행 검증`, `사용자 확인`, `미검증`으로 구분하고 증거를 연결한다. 글꼴 cmap 수록, 대표 글리프 래스터화, 실제 모든 화면 LQA는 서로 다른 검증이다. 실행 로그의 게임 진입만으로 화면 배치가 정상이라고 결론짓지 않는다.

IME, 정규화·조합 문자, 사용자 이름, 저장·로드, 채팅·네트워크는 정적 UI 번역과 별도로 다룬다. 사용자 확인은 확인한 화면·버전·수정 전후를 적고 전체 회귀 검증으로 확대하지 않는다.

## 정규화된 카탈로그 검사

`scripts/validate_catalog.py`는 Python 3.9 이상 표준 라이브러리만 사용한다. 입력은 UTF-8 JSON 객체이며 각 값은 문자열이어야 한다.

```json
{
  "100": "{COLOUR BLACK}새 게임",
  "101": "{INT16}명"
}
```

이 계열의 원본 YAML은 실제 yaml-cpp 로더에서 파싱하고 `strings`의 숫자 ID와 문자열 값을 평면 JSON으로 정규화한다. 중복 ID는 원본 파싱 단계에서도 검사한다. 보조 파서를 사용하면 `=`·빈 문자열·따옴표·이스케이프와 숫자 키의 의미가 실제 로더와 같은지 대조한다. YAML의 암묵적 bool·number 해석으로 번역 값을 바꾸지 않는다. 정규화 후 검사는 원본 파싱 검증을 대체하지 않는다.

파일 경로는 사용 환경에 맞게 지정한다.

```text
python scripts/validate_catalog.py source.json target.json --token-pattern "\{[^{}\r\n]+\}" --output validation.json
```

토큰 패턴은 대상 포맷에 맞춰 `--token-pattern`으로 지정하며 여러 번 줄 수 있다. 지정하지 않으면 키·문자 데이터만 검사하고 **토큰 미검사**를 결과에 명시한다. 위 중괄호 패턴은 단순 예시다. 중첩 ICU 메시지, 엔진 이스케이프, printf 인수의 의미·자료형·소비 순서를 정규식만으로 검증했다고 판단하지 않는다. 해당 포맷의 실제 파서를 사용한다.

스크립트가 확인하는 범위:

- 중복 JSON 키, 비문자열 값, 잘못된 인코딩·유효하지 않은 Unicode 값
- 누락·추가 문자열 ID와 토큰의 정확한 순서·내용
- 검토된 예외의 현재 원문·번역 토큰 일치 여부
- 번역 표시 부분의 고유 코드포인트와 한글 수, NFC가 아닌 항목, 대체 문자 존재

NFC 차이와 U+FFFD는 기본적으로 경고다. 대상의 요구에 따라 판단하며 스크립트는 원본을 자동 정규화하거나 수정하지 않는다. 빈 카탈로그는 추출 실패를 구분할 수 없으므로 오류다.

## 검토된 토큰 예외

일반 예외 허용으로 검사를 끄지 않는다. 어순이나 레이아웃 변경을 검토했다면 정확한 기대 토큰열과 이유를 예외 파일에 기록한다.

```json
{
  "102": {
    "reason": "인수 소비 순서는 유지되며 한국어 문장에 맞춰 줄바꿈 위치만 이동한다.",
    "source_tokens": ["{COLOUR BLACK}", "{NEWLINE}", "{STRINGID}"],
    "target_tokens": ["{COLOUR BLACK}", "{STRINGID}", "{NEWLINE}"]
  }
}
```

```text
python scripts/validate_catalog.py source.json target.json --token-pattern "\{[^{}\r\n]+\}" --exceptions token-exceptions.json
```

원문·번역이 예외에 기록한 값과 달라지거나 예외가 더 이상 필요 없으면 오류로 처리해 다시 검토하게 한다. 예외 파일은 인수 순서 변경이 엔진에서 안전하다는 증거가 아니며, 게임 측 포맷 의미를 별도로 확인해야 한다.

종료 코드는 `0`: 수행한 검사 통과, `1`: 키·토큰 불일치, `2`: 입력·설정 오류다. 출력 보고서의 `token_check`를 확인해 미검사를 통과로 오인하지 않는다.

## 글꼴과 화면 검증

이 엔진의 C++ 회귀 검증은 다음 불변식을 우선 확인한다. 현재 변경과 관계없는 항목은 기존 통과 근거를 재사용한다.

1. 한글 코드포인트가 5바이트 표시 토큰으로 보존되고 실제 `?`·라틴·G1 아이콘은 원래 경로를 사용한다.
2. 인수에 0바이트가 있어도 다중 한글을 복사하며, 버퍼 끝에서 태그·인수를 분할하지 않는다.
3. GDI로 만든 대표 한글이 비어 있지 않고 8비트 화면 버퍼의 선택 색상으로 출력된다.
4. 음수 창 좌표·클리핑·행 padding에서도 같은 로컬 글리프가 나오고 버퍼 밖을 쓰지 않는다.
5. 혼합 문자 경계의 추가 폭을 그리기·측정이 똑같이 반영하며 한글끼리의 간격은 의도대로 유지된다.
6. DAT 매핑의 종류·인덱스·포맷 인수와 미등록 원문 폴백이 보존된다.

실행 확인은 언어 선택 목록, 옵션, 튜토리얼, 건설·차량·회사, 뉴스·티커, 오브젝트 선택과 장문 툴팁을 변경 범위에 맞게 고른다. 고정 길이 시나리오·회사 이름과 저장·로드는 별도 확인한다.

보고서의 `display_codepoints`는 사용한 토큰 패턴이 잡아낸 부분을 제외한 번역 문자 집합이다. 폰트의 cmap·아틀라스와 대조할 때 사용한다. 선택한 패턴이 텍스트를 잘못 제거했거나 실제 표시 문자가 런타임 인수에서 추가되면 그 문자도 따로 포함한다.

fontTools 또는 엔진의 폰트 도구가 있으면 문자 집합의 수록 여부를 확인한다. 그 후 대표·복잡한 한글과 장문을 실제 렌더러로 출력해 기준선, 획, 캐시, 정렬, 색상과 클리핑을 검증한다. 글꼴 수록이 shaping·자모 조합·IME·모든 화면의 정상을 보장하지 않는다.

화면 조작 도구를 사용할 수 없거나 승인되지 않으면 해당 부분을 미검증으로 남기고 정적 검사·빌드·패키지 작업을 완료한다. 사용자가 직접 확인한 결과를 받아 문제 표면만 수정하며 확인하지 않은 화면을 성공으로 보고하지 않는다.
