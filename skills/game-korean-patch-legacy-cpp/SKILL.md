# 레거시 C++ 운송 시뮬레이션 한글화

대상은 원작의 데이터·저장 구조를 이어받은 C++ 재구현 엔진이다. UTF-8 YAML을 1바이트 내부 문자열로 바꾸고 G1 글리프를 8비트 팔레트 화면에 그리는 구조에 특화한다. 필요한 구조·구현·검증 지식은 이 패키지 안에 포함한다. 호출명은 `$game-korean-patch`를 유지한다.

## 1. 설치본과 소스에서 시작

먼저 [references/engine-profile.md](references/engine-profile.md)를 읽고 설치 루트와 대응 소스를 찾는다. CMake 버전·실행 파일 식별 정보·대표 해시를 수집하고, YAML 언어 파일과 문자 변환·G1 렌더러라는 독립된 근거를 확인한다. 구조가 다른 대상은 이 방식을 억지로 적용하지 말고 불일치한 부분을 설명한다.

현재 소스·게임 데이터·사용자의 작업 요청이 시작 입력이다. 이전 패치가 있으면 변경 사항을 재사용하되 없어도 이 패키지의 절차로 진행한다. 소스가 없으면 설치 버전에 맞는 공식 소스 확보 가능성을 확인한다. 외부 분석 문서의 작성·탐색·제출을 선행 조건으로 두지 않는다.

실행 파일·교체할 YAML·글꼴을 백업하고 버전과 SHA-256을 기록한다. 원작 DAT·세이브는 보존하고 소스·빌드·실행 검증·배포 staging을 분리한다. 필요한 로컬 구현·빌드·검증은 요청 범위에서 진행하며, 단계마다 승인을 반복해서 요청하지 않는다.

## 2. 구현 순서

코드 수정 시 [references/implementation.md](references/implementation.md)를 읽는다.

1. **로케일과 번역:** `language/*.yml`의 헤더와 숫자 문자열 ID를 파싱한다. 기존 `ko-KR`이 있으면 보완하고, 기준 영어 선로드·선택 언어 덮어쓰기·원작 언어 ID 연결을 유지한다.
2. **문자 보존:** YAML의 일반 문자와 `{...}` 포맷 명령을 구분한다. 한글이 `?`로 바뀌는 변환 경계를 찾아 기존 문자·아이콘은 보존하고 미지원 문자를 표시용 유니코드 토큰으로 전달한다. 언어명 `native_name`에도 같은 경로를 적용한다.
3. **글꼴 출력:** G1 라틴 글리프를 유지하면서 미지원 코드포인트만 동적 글리프 공급자로 보낸다. Windows에서는 프로세스 전용 글꼴 등록·GDI 래스터화·팔레트 출력·캐시를 우선 구현 경로로 삼는다. 다른 OS의 출력 지원은 해당 공급자 구현과 검증이 필요하다.
4. **혼합 문자열:** 내장 NULL과 인수 길이를 이해하는 복사·길이 계산을 포맷·뉴스·티커·로딩·시나리오·회사 이름 경로에 적용한다. 토큰을 중간에서 나누지 않는다.
5. **폭과 배치:** 그리기·줄바꿈·자르기·정렬·커서가 같은 폭·문자 경계를 사용하게 한다. 기준선·혼합 문자 자간·행 높이·툴팁 여백은 한국어 표면에서 조정한다.
6. **DAT 명칭:** UI YAML과 별개인 오브젝트 문자열 로더를 확인한다. 원본 DAT 대신 한국어 로딩 시 종류·ID·문자열 인덱스에 한정한 매핑을 사용하고 미등록 콘텐츠는 원문으로 폴백한다.

사용자가 번역·글꼴·UI 수정만 요청하면 이미 구현·검증된 경로를 유지하고 필요한 단계만 수행한다. 소스 재빌드 대신 이전 실행 파일을 현재 버전 위에 덮어쓰지 않는다.

## 3. 유지할 호환성

- 이 엔진의 표시 문자열은 일반 UTF-8 또는 일반 NULL 종료 문자열과 다르다. 태그·바이너리 인수·포맷 전후 상태를 구분한다.
- 새 유니코드 태그는 현재 버전의 미사용 영역과 인수 길이를 확인한 뒤 정한다. 특정 번호가 계속 비어 있다고 가정하지 않는다.
- `{STRINGID}`, 정수·통화 토큰, `{POP16}`, 색상·글꼴·인라인 스프라이트의 의미와 인수 소비 순서를 보존한다. 토큰 순서 예외는 실제 포맷 의미를 검토한 뒤 기록한다.
- 저장 필드·오브젝트 원본·네트워크 패킷까지 표시용 토큰으로 일괄 변환하지 않는다. 필드 길이·비패치 실행 파일과의 호환성을 별도로 다룬다.
- `hang.dat`·`kanji.dat`·`tai.dat` 같은 자산이나 CJK 로케일이 있어도 현재 출력에 사용된다고 단정하지 않는다. 한글이 먼저 소실되면 글꼴 교체나 슬롯 변경만으로 해결되지 않는다.
- 이 엔진은 기본 medium normal/bold·small·large의 글꼴 경로를 모두 확인해야 한다. 한 화면의 출력 성공을 전체 UI 지원으로 확대하지 않는다.

## 4. 검증·버전 갱신·배포

검증 시 [references/validation.md](references/validation.md)를 읽는다. 실제 yaml-cpp 파싱, 키·토큰 대조, 글리프 수록과 대표 래스터화, 내장 NULL 복사·안전 절단, 폭·클리핑·티커, 기존 필수 테스트와 변경 화면을 확인한다. `scripts/validate_catalog.py`는 정규화한 평면 JSON 맵의 검사 도구이며 원본 파서와 C++ 포맷·렌더러 테스트를 대신하지 않는다.

이식·설치·배포 시 [references/release.md](references/release.md)를 읽는다. 대응 버전의 C++·CMake·의존성·자산에 변경을 이식하고 깨끗한 기준 소스에 최종 패치를 재적용한다. 교체 대상·백업·필수 파일·라이선스와 설치본·staging·ZIP의 해시를 대조한다. 확인되지 않은 런처·스토어 실행 파일까지 교체하지 않는다.

사용자가 작업 중인 게임을 임의 종료하지 않는다. 파일 잠금이나 권한 제약이 있으면 빌드·패키지 등 독립 작업을 마친 뒤 필요한 조치만 요청한다. 보호 기능 우회는 구현 경로로 사용하지 않는다.

결과는 [assets/KOREAN_PATCH_RESULT.template.md](assets/KOREAN_PATCH_RESULT.template.md)를 필요에 맞게 작성한다. 버전·구조 확인 근거, 수정 파일·소스·배포물, 백업·원복, 실행한 검증과 남은 범위를 기록한다. 정적 검증·직접 실행·사용자 확인을 구분하고 입력 IME나 전체 저장 호환성까지 검증했다고 추정하지 않는다.
